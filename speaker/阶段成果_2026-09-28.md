# i.MX6ULL 智能语音交互终端阶段成果

## 1. 项目目标

基于 i.MX6ULL + WM8960 制作一个智能语音交互终端。

整体架构：

```text
                        i.MX6ULL
                           │
          ┌────────────────┼────────────────┐
          │                │                │
       ALSA采集          会话管理          网络管理
          │                │                │
      PCM / AEC          FSM状态机        HTTP/重连
          │                │                │
          └────────────────┼────────────────┘
                           │
                      FastAPI Server
                           │
                 ASR → LLM → TTS
                           │
                       音频播放
```

当前一周版本的原则是：

- i.MX6ULL 负责音频采集、播放、状态管理和网络通信。
- Ubuntu/FastAPI 负责 ASR、LLM、TTS。
- 第一阶段先跑通完整链路，再增加 AEC、VAD、唤醒词和多线程。

## 4. Buildroot Rootfs 合入 NFS Rootfs

Buildroot 编译输出目录：

```bash
~/linux/buildroot-2022.02.10/output/target/
```

当前 NFS 根文件系统：

```bash
/home/huanyu/linux/rootfs_nogpu/
```

同步时遇到：

```text
could not make way for new symlink: var/lock
could not make way for new symlink: var/log
could not make way for new symlink: var/run
```

原因：

Buildroot 的 output/target 中这些路径可能是符号链接，而原有 NFS rootfs 中是非空真实目录。

推荐同步命令：

```bash
sudo rsync -aHAX --numeric-ids \
  --exclude='/dev/*' \
  --exclude='/proc/*' \
  --exclude='/sys/*' \
  --exclude='/tmp/*' \
  --exclude='/run/*' \
  --exclude='/var/lock' \
  --exclude='/var/log' \
  --exclude='/var/run' \
  ~/linux/buildroot-2022.02.10/output/target/ \
  /home/huanyu/linux/rootfs_nogpu/
```

注意：

直接整体同步可能覆盖：

```text
/etc/passwd
/etc/shadow
/etc/inittab
/etc/profile
```

这会导致开发板重启后出现登录账号/密码要求。

后续若只是补充软件包，应谨慎覆盖 /etc。

## 5. ALSA 录音基础命令

常用录音命令：

```bash
arecord -D hw:0,0 -f S16_LE -r 16000 -c 1 -d 5 /tmp/test.wav
```

参数：

```text
-D = device
-f = format
-r = rate
-c = channels
-d = duration
```

含义：

```text
设备：hw:0,0
格式：S16_LE
采样率：16000 Hz
声道：1
时长：5 秒
```

## 8. 同时播放和录音测试

后台播放：

```bash
aplay test.wav &
```

一开始尝试录音：

```bash
arecord -D hw:0,0 -f S16_LE -r 16000 -c 1 -d 10 capture.wav
```

出现：

```text
arecord: set_params:1349: Channels count non available
```

当时播放参数是：

```text
S16_LE
22050 Hz
2 channels
```

而录音请求是：

```text
S16_LE
16000 Hz
1 channel
```

两边参数不一致。

因此当前不能直接得出“WM8960 不支持全双工”的结论。

下一步应该使用相同参数测试：

```bash
aplay test.wav &
arecord -D hw:0,0 -f S16_LE -r 22050 -c 2 -d 10 capture.wav
```

目标是验证：

```text
Playback 和 Capture
是否能够同时工作
```

如果能同时工作，则说明当前 i.MX6ULL + WM8960 + ASoC 链路具备全双工基础能力，只是参数需要保持兼容。

## 13. AEC 的技术判断

这个项目后续需要解决：

```text
扬声器正在播放 TTS
+
用户同时说话
↓
麦克风会同时采到：
用户声音 + 扬声器回声
```

WM8960 本身不是专用 AEC DSP。

正确的软件链路应该是：

```text
Playback PCM ───────► WM8960 DAC ─────► Speaker
      │                                    │
      │                                    │ Echo
      │                                    ▼
      └────► Reference Buffer         Microphone
                                      │
                                      ▼
                                  WM8960 ADC
                                      │
                                   Mic PCM
                                      │
                     Reference PCM ───┤
                                      ▼
                                     AEC
                                      │
                                  Clean PCM
                                      │
                                     VAD
                                      │
                                     ASR
```

AEC 至少需要两路输入：

1. 麦克风采集的 Mic PCM。
2. 实际送入扬声器的 Playback Reference PCM。

不能简单执行：

```text
Mic PCM - Playback PCM
```

因为扬声器到麦克风之间存在：

- 声学传播延迟
- 房间反射
- 扬声器响应
- 麦克风响应
- ALSA Buffer
- DMA
- Codec 延迟

所以后续需要：

```text
Reference Ring Buffer
+
Mic Ring Buffer
+
延迟对齐
+
AEC
```

第一周建议先完成半双工主链路，全双工 AEC 作为第二阶段。
